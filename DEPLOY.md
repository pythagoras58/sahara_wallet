# Deploying Sahara Wallet (free tier)

Stack: **Vercel** (web) + **Render** (API) + **Neon** (Postgres). All free, no card required.

Known limitation: KYC document uploads are stored on local disk. Render's free tier has an
ephemeral filesystem, so uploaded files disappear on redeploy/restart. Fine for a feedback
test, not fine long-term -- revisit before this goes further.

## 0. Push the code to GitHub

Render and Vercel both deploy from a connected Git repo. This repo is already `git init`'d
locally with nothing committed yet.

```bash
git add -A
git commit -m "Initial commit"
```

Then create a new repo on github.com (empty, no README/license), and:

```bash
git remote add origin <your-repo-url>
git branch -M main
git push -u origin main
```

## 1. Database — Neon

1. Sign up at neon.tech (free, no card).
2. Create a project (any name/region).
3. Copy the connection string it gives you (starts `postgresql://...`, includes
   `?sslmode=require`) -- you'll need it twice, in steps 2 and 3 below.
4. From your own machine, apply the schema and seed it once:
   ```bash
   cd apps/api
   set DATABASE_URL=<neon-connection-string>   # Windows cmd; use $env:DATABASE_URL= in PowerShell
   npx prisma migrate deploy
   npx prisma db seed
   ```

## 2. API — Render

1. Sign up at render.com (free, no card) and connect your GitHub account.
2. New → Blueprint → pick this repo. Render reads `render.yaml` at the repo root and sets
   up the `sahara-api` service automatically.
3. Before the first deploy, fill in the environment variables it leaves blank:
   - `DATABASE_URL` — the same Neon connection string from step 1
   - `CORS_ORIGIN` — leave as `http://localhost:3001` for now, you'll update it in step 4
   - `CIRCLE_API_KEY` / `CIRCLE_ENTITY_SECRET` — leave blank unless you want your colleague
     testing the on-chain wallet features too
   - `JWT_SECRET` is auto-generated by the blueprint, no action needed
4. Deploy. First build takes a few minutes. Once live, note the URL Render gives you
   (`https://sahara-api-xxxx.onrender.com`).

Free-tier heads up: the service sleeps after 15 minutes idle. The first request after a
sleep takes ~30-50 seconds to wake up -- not a bug, just the free tier.

## 3. Web app — Vercel

1. Sign up at vercel.com (free, no card) and connect your GitHub account.
2. New Project → pick this repo.
3. Set **Root Directory** to `apps/web` (Vercel auto-detects Next.js and handles the npm
   workspace install correctly from there).
4. Add environment variable `NEXT_PUBLIC_API_URL` = the Render URL from step 2.
5. Deploy. Note the URL Vercel gives you (`https://sahara-wallet-xxxx.vercel.app`).

## 4. Close the loop

Back in Render, update the `sahara-api` service's `CORS_ORIGIN` env var to the Vercel URL
from step 3 (comma-separated if you want to keep `http://localhost:3001` too, for your own
local dev). Save -- Render redeploys automatically on env var changes.

That's it. Send your colleague the Vercel URL and the test logins from
`Sahara_Wallet_Setup_Guide.docx` (or `README.md`'s Auth section).
